# SPEC-004: Пайплайн данных V20 → фикстуры

> Статус: TODO · Фаза: 1 · Зависит от: SPEC-003

## Цель

Наполнить справочник `rules` корректными данными V20: распарсить источники в
структурированные фикстуры (кланы, атрибуты, способности, дисциплины, бэкграунды,
добродетели, архетипы, поколения, правила создания) и загрузить их командой.
**Владелец проекта валидирует данные вручную** перед фиксацией.

## Контекст / ссылки

- [02-domain-v20.md](../02-domain-v20.md) — полные списки и числа (атрибуты,
  способности 10/10/10, дисциплины, кланы, таблица поколений, freebie).
- [03-data-model.md](../03-data-model.md) — целевые модели.
- Юр. ограничения: [02 §Юридические ограничения](../02-domain-v20.md#юридические-ограничения).

## Скоуп

**В работе:**
- Скрипт/management-команда парсинга источников в промежуточный
  структурированный формат (JSON/YAML) в `rules/data/`.
- Преобразование в **Django-фикстуры** (или загрузка напрямую командой
  `loaddata`/кастомной `seed_v20`). Идемпотентность: повторный запуск не плодит дубли
  (upsert по `(line, category, code)` / `(line, code)`).
- Наполнить: `GameLine=vampire`; 9 атрибутов (с `subgroup`); 30 способностей
  (talents/skills/knowledges); список дисциплин; кланы V20 + их клановые дисциплины
  + краткая (своими словами) слабость; архетипы (nature/demeanor); `GenerationStat`
  (таблица поколений); правила создания (7/5/3, 13/9/5, freebie-стоимости) —
  как данные.
- Каждой записи — поле/мета **источник** (origin), чтобы отличать
  спарсенное/проверенное.
- Короткий README по запуску пайплайна и формату данных.

**Не трогаем:**
- `DisciplinePower` (силы по уровням), мериты/флоу целиком, пути/ритуалы — бэклог;
  можно оставить заготовки.
- API-выдачу `creation-rules` (SPEC-006) — здесь только данные.

## Критерии приёмки

- [ ] Команда `python manage.py seed_v20` (имя на усмотрение) идемпотентно
      загружает каталог; повторный запуск не создаёт дублей.
- [ ] В БД: 1 линейка, 9 атрибутов, 30 способностей, все клановые дисциплины,
      кланы V20 с проставленными клановыми дисциплинами, архетипы, таблица
      поколений, числа создания.
- [ ] Данные видны и корректны в админке (готовы к ручной валидации владельцем).
- [ ] **Описательные тексты — не дословные копии книг** (summary своими словами
      или пусто); у записей проставлен источник.

## Заметки по реализации

- Парсер изолировать (`rules/data/parse_*.py`); фикстуры — артефакт, который
  владелец просматривает в diff перед коммитом.
- Дисциплины — это `Trait(category=discipline)`; кланы ссылаются на них M2M.
- Числа создания: предложить и согласовать формат хранения (отдельная модель
  `CreationRule`/`PriorityPreset` или строки в `GenerationStat`/конфиг-фикстуре);
  зафиксировать в [03-data-model.md](../03-data-model.md) при реализации.
- Названия трейтов/кланов — оставить и на английском (code), и локализованное имя
  (под будущую i18n RU/EN).

## Затрагиваемые файлы (ориентир)

- `rules/data/` (сырьё + фикстуры), `rules/management/commands/seed_v20.py`
- возможно правки `rules/models.py` (поле origin / модель правил создания)

## Тесты

- После `seed_v20` — счётчики записей соответствуют ожидаемым; повторный запуск
  не меняет количество; у клана Ventrue корректный набор клановых дисциплин (спот-чек).

## Definition of Done

Каталог V20 загружается одной командой, идемпотентно, проверяемо в админке,
без копипасты текстов, готов к ручной валидации владельцем.
