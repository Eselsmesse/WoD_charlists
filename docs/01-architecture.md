# 01. Архитектура

## Стек (зафиксировано)

| Слой | Технология | Примечание |
|------|-----------|-----------|
| Backend | **Django 5.2 + Django REST Framework** | API-first |
| БД (dev) | SQLite | как сейчас |
| БД (prod) | **PostgreSQL** | для JSONB, full-text, pgvector под RAG |
| Frontend | **SPA** (по умолчанию React + Vite + TypeScript) | см. «Открытые решения» |
| Аутентификация | JWT (djangorestframework-simplejwt) | см. ADR-0003 |
| ИИ-генерация | внешний **LLM API** + RAG | провайдер за абстракцией, см. [05](05-ai-quenta-spec.md) |
| Векторный поиск | pgvector (prod) / в памяти или sqlite-vec (dev) | для RAG |
| Очереди (позже) | Celery + Redis | генерация квенты асинхронно, когда понадобится |

## Структура репозитория (целевая)

Сейчас проект живёт в `wod_charlists/` с приложениями `main` и `storage`.
Целевая структура переразбивает домен на осмысленные приложения:

```
WoD_charlists/
├── docs/                      # эта документация
├── backend/                   # (переименование/перенос текущего wod_charlists/)
│   ├── manage.py
│   ├── config/                # бывш. wod_charlists/ — settings, urls, wsgi/asgi
│   │   ├── settings/          # base.py / dev.py / prod.py
│   │   └── urls.py
│   ├── accounts/              # пользователи, профиль, аутентификация
│   ├── rules/                 # КАТАЛОГ правил V20 (кланы, дисциплины, трейты) — read-only справочник
│   ├── characters/            # персонажи, трейты персонажа, теги, группы
│   ├── sharing/               # публичные ссылки, права на просмотр
│   ├── quenta/                # ИИ-генерация: провайдеры, RAG, промпты
│   └── requirements/          # base.txt / dev.txt / prod.txt
├── frontend/                  # SPA (создаётся в фазе 3)
└── README.md
```

> Текущие приложения `main` (демо-презентация) и `storage` (стартовые модели
> `SystemDefinition`, `Character`) — временные. `storage` эволюционирует в
> `rules` + `characters`; `main` убирается, когда фронт переедет в SPA.
> Решение о физическом переносе папок — в [SPEC-001](specs/SPEC-001-project-hygiene.md).

## Разбиение на Django-приложения

- **accounts** — кастомная модель пользователя (или профиль), регистрация, JWT.
- **rules** — справочник правил V20: `GameLine`, `Clan`, `Trait` (атрибуты,
  способности, дисциплины, бэкграунды, добродетели), `DisciplinePower`,
  `Merit`, `Flaw`, `Archetype`. **Данные, не пользовательский контент.** Read-only
  через API; наполняется фикстурами/парсером.
- **characters** — `Character`, `CharacterTrait`, `Tag`, `CharacterGroup` (партии).
  Принадлежат пользователю, CRUD.
- **sharing** — `ShareLink` (публичная read-only ссылка по токену).
- **quenta** — `Narrative` (версии квенты), `GenerationRequest`, RAG-хранилище
  (`LoreDocument`, `LoreChunk`), `CitySetting` (контекст города).

Принцип: **`rules` = факты правил (общие для всех)**, **`characters` = данные
пользователя**. Это разделение — ключ к расширяемости на другие линейки.

## Конфигурация и окружение

- Настройки разбиваются на `config/settings/{base,dev,prod}.py`.
- Секреты — через переменные окружения (`django-environ` или `os.environ` + `.env`),
  **не в коде**. Текущий хардкод `SECRET_KEY` и `DEBUG=True` выносятся.
- `.env.example` коммитится, `.env` — в `.gitignore`.
- `db.sqlite3` и `__pycache__` **убрать из гита** (сейчас затрекано — баг, см. SPEC-001).

## Решения (ADR — кратко)

| ID | Решение | Почему | Альтернатива (отклонена) |
|----|---------|--------|--------------------------|
| 0001 | Старт только с V20 (Vampire) | Минимальный честный MVP, отладка архитектуры на одной линейке | Все линейки сразу — риск утонуть в данных |
| 0002 | DRF + SPA | Запрос пользователя; промышленный паттерн; учит API-стороне Django | HTMX/шаблоны — меньше интерактива |
| 0003 | JWT-аутентификация | Stateless, удобно для SPA | Session-auth — проще, но связывает фронт с куками/CSRF |
| 0004 | LLM API + RAG (без обучения) | Быстро, без GPU/датасета; качество за счёт промпта и лора | Дообучение LoRA — дорого и преждевременно |
| 0005 | Провайдер ИИ за абстракцией | Сменить провайдера / уйти на свою модель без правок домена | Прямые вызовы SDK из вьюх — жёсткая связанность |
| 0006 | `rules` отдельно от `characters` | Расширяемость на линейки; справочник переиспользуется | Всё в одной модели + JSON — плохо запрашивается |
| 0007 | Гибрид: ядро в колонках, гибкие трейты в связной таблице `CharacterTrait` | Запрашиваемость (фильтры/теги) + гибкость | Чистый JSONField — теряем валидацию и запросы |

## Открытые решения (требуют выбора владельца — не блокируют старт)

1. **Фреймворк SPA.** По умолчанию закладываем **React + Vite + TypeScript**
   (макс. экосистема и материалов). Альтернатива — Vue. Не блокирует бэкенд;
   решается к фазе 3.
2. **Хостинг/деплой.** Кандидаты: VPS + Docker Compose, или PaaS (Railway/Render/Fly).
   Решается к фазе 6. На разработку не влияет.
3. **Провайдер LLM.** По умолчанию — Anthropic Claude (например `claude-sonnet-4-6`
   как баланс цена/качество для генерации текста). За абстракцией провайдера легко
   заменить. Детали — в [05-ai-quenta-spec.md](05-ai-quenta-spec.md).
