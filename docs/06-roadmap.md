# 06. Дорожная карта

Фазы упорядочены по зависимостям. Каждая веха — набор спек в [specs/](specs/).
Цель — всегда иметь рабочее состояние в конце фазы.

## Фаза 0 — Фундамент

Привести скелет в порядок, поставить рельсы.

- [SPEC-001](specs/SPEC-001-project-hygiene.md) — гигиена проекта: разнести
  settings (base/dev/prod), `.env`, requirements, убрать `db.sqlite3`/`__pycache__`
  из гита, вынести `SECRET_KEY`/`DEBUG`.
- [SPEC-002](specs/SPEC-002-drf-setup.md) — DRF + CORS + JWT-каркас, `/api/v1/`,
  кастомная модель пользователя.

**Готово, когда**: сервер поднимается, `/api/v1/auth/...` отвечает, настройки
читаются из env, гит чистый.

## Фаза 1 — Домен и данные V20

- [SPEC-003](specs/SPEC-003-domain-models.md) — модели `rules` + `characters`
  (по [03](03-data-model.md)), миграции, админка. Упразднить `storage`.
- [SPEC-004](specs/SPEC-004-rules-data-pipeline.md) — пайплайн данных: парсер
  источников → фикстуры (кланы, атрибуты, способности, дисциплины, бэкграунды,
  добродетели, архетипы, поколения, freebie). Пометка источника, без копипасты.
  Загрузка фикстур командой. **Владелец валидирует руками.**

**Готово, когда**: в БД лежит корректный каталог V20, видимый в админке;
персонажа можно создать с трейтами через админку.

## Фаза 2 — Аутентификация и API персонажей

- [SPEC-005](specs/SPEC-005-auth-api.md) — регистрация/логин/refresh/me.
- [SPEC-006](specs/SPEC-006-characters-api.md) — CRUD персонажей, сериализаторы
  (list/detail), bulk-апсерт трейтов, права `IsOwner`, фильтры.
- [SPEC-007](specs/SPEC-007-tags-groups.md) — теги и группы (комплектование).
- [SPEC-008](specs/SPEC-008-sharing.md) — публичные ссылки read-only + копия себе.

**Готово, когда**: через API можно зарегистрироваться, создать/отредактировать/
удалить персонажа, тегировать, расшарить ссылкой. Покрыто тестами.

## Фаза 3 — Фронтенд SPA

- SPEC-009 — каркас SPA (React+Vite+TS), env-конфиг API, аутентификация (хранение
  токенов, refresh-флоу), роутинг.
- SPEC-010 — экран списка персонажей: фильтры по тегам/группам, поиск, создание.
- SPEC-011 — редактор чарника: точки атрибутов/способностей/дисциплин, дескрипторы,
  автосейв (bulk-апсерт), индикатор лимитов создания (по `creation-rules`).
- SPEC-012 — экран шеринга и публичный read-only просмотр.

**Готово, когда**: весь путь MVP проходится в браузере без админки.

## Фаза 4 — Квента (ИИ)

- SPEC-013 — абстракция `QuentaProvider` + реализация на внешнем API, env-конфиг,
  лог `GenerationRequest`, лимиты/бюджет.
- SPEC-014 — RAG: модели `LoreDocument/LoreChunk/CitySetting`, ингест лора,
  ретривер (dev: в памяти; prod: pgvector), `PromptBuilder`, шаблоны промптов.
- SPEC-015 — эндпоинт генерации + версии `Narrative` + промоут в `history`.
- SPEC-016 — UI квенты в SPA: параметры, генерация, просмотр версий, правка.

**Готово, когда**: по кнопке генерируется осмысленная квента, объясняющая статы
с учётом города; версии сохраняются и редактируются.

## Фаза 5 — Полировка и деплой

- SPEC-017 — экспорт чарника в PDF/печать.
- SPEC-018 — переезд на PostgreSQL (+pgvector), Docker Compose.
- SPEC-019 — деплой (выбранный хостинг), HTTPS, прод-настройки, дисклеймер Dark Pack.
- SPEC-020 — CI (GitHub Actions): линт + тесты на PR.

## Расширения (бэклог, вне MVP)

- Другие линейки: Werewolf / Mage / Hunter / Changeling (наполнение `rules`).
- **Обратная задача** «история → статы».
- **Дообучение** собственной модели за абстракцией провайдера.
- Валидатор создания персонажа (жёсткая проверка лимитов 7/5/3, 13/9/5, freebie).
- Дисциплины с путями/ритуалами (Thaumaturgy/Necromancy), `DisciplinePower`.
- Асинхронная генерация (Celery+Redis), стриминг квенты.
- Совместный доступ ST к партии, комментарии.

## Зависимости (порядок обязателен)

Ф0 ─► Ф1 ─► Ф2 ─► Ф3
              └──► Ф4  (нужны персонажи и трейты; UI квенты — после Ф3)
Ф5 — поверх готового MVP.
