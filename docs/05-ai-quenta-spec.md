# 05. Квента: ИИ-генерация (LLM API + RAG)

Главная фича. На старте — **прямая задача**: статы + контекст → художественная
квента, объясняющая, *почему* у персонажа такие характеристики. Обратная задача
(история → статы) — **отдельная веха после MVP**, здесь только заложена точка
расширения.

## Подход (ADR-0004/0005)

- **Без собственного обучения на старте.** Берём внешний LLM через API.
- **RAG**: к запросу подмешиваем релевантные куски лора (клан, дисциплины,
  сеттинг города), чтобы модель писала «в каноне» и связно.
- **Провайдер за абстракцией** — чтобы сменить модель/провайдера или позже
  подключить дообученную модель без правок домена.

```text
 статы персонажа (Character + CharacterTrait)
            │
            ▼
   PromptBuilder ──► формирует структурированное описание персонажа
            │              (атрибуты с акцентом на пиковые/слабые трейты)
            ▼
   RAGRetriever ──► top-k LoreChunk (клан, дисциплины, CitySetting) по embeddings
            │
            ▼
   QuentaProvider.generate(system, context, params) ──► LLM API
            │
            ▼
   Narrative (текст + params + provider/model) ──► сохраняется как версия
```

## Абстракция провайдера

```python
class QuentaProvider(Protocol):
    def generate(self, *, system: str, prompt: str, params: GenParams) -> GenResult: ...

# реализации: AnthropicProvider (по умолчанию), затем — свой fine-tuned эндпоинт.
```

- Конфиг провайдера/модели/ключа — через переменные окружения, **не в коде**.
- По умолчанию — Anthropic Claude; для генерации текста разумен баланс качество/цена
  (напр. модель уровня Sonnet). Конкретный `model` хранится в `Narrative.model`.
- **При реализации** свериться с актуальным API: см. навык `claude-api`
  (модели, параметры, стриминг, подсчёт токенов, кэширование).

## Вход (что собираем в промпт)

1. **Профиль персонажа**: clan, generation, sect, nature/demeanor, concept.
2. **Трейты с акцентами**: выделяем пиковые (4–5) и нулевые трейты — именно их
   история должна «оправдать» (высокая Strength+Brawl → бокс/уличные драки;
   высокая Occult → оккультные изыскания; низкая Appearance → шрамы/замкнутость).
3. **Дескрипторы**: возраст, внешность, дата обращения.
4. **Контекст города** (`CitySetting`): политика сект, тон, локации.
5. **Параметры генерации** (`GenParams`): язык (ru/en), длина, тон
   (мрачный/нуар/романтичный), фокус (на каком периоде жизни), POV.

## RAG-хранилище

- `LoreDocument` → нарезается на `LoreChunk` (текст + embedding).
- Источники лора — **оригинальные/переписанные** материалы (не дословные книги,
  см. юр. ограничения), плюс пользовательские `CitySetting`.
- Dev: эмбеддинги в SQLite/в памяти; Prod: **pgvector**.
- Ретривер: top-k по косинусному сходству, фильтр по линейке/клану/городу.

## Дизайн промпта (скелет)

- **System**: роль — рассказчик WoD V20; правила тона; запрет ломать канон;
  требование связать конкретные статы с биографией; язык вывода.
- **Context (RAG)**: вставленные чанки лора с пометкой источника.
- **User**: структурированное описание персонажа + явный список «объясни эти
  пиковые/нулевые трейты».
- Промпты — **шаблоны в `quenta/prompts/`** (версионируются), а не строки в коде.

## Поток и API

`POST /api/v1/characters/{id}/quenta/generate/` (тело — `GenParams` + `city`):

1. Собрать профиль и трейты персонажа (проверить владельца).
2. RAG-ретрив контекста.
3. Вызвать провайдера; залогировать `GenerationRequest` (статус, токены, стоимость).
4. Сохранить результат как `Narrative` (новая версия), вернуть текст.
5. Пользователь редактирует и/или «промоутит» версию в `Character.history`.

**Синхронно** на старте (одна генерация — несколько секунд). Когда упрётся в
таймауты/нагрузку — вынести в **Celery + Redis** (заложено, не делаем сразу).

## Безопасность, стоимость, надёжность

- Ключи API — только в env; не логировать.
- **Лимиты**: rate-limit на пользователя, лимит длины вывода, дневной бюджет.
- Логировать токены/стоимость в `GenerationRequest` для контроля затрат.
- Грейсфул-фолбэк при ошибке провайдера (понятная ошибка, не 500-стектрейс).
- Не подавать в модель чужие приватные данные; город/лор — общий или личный.

## Оценка качества (как поймём, что работает)

- Чек-лист: упомянуты ли пиковые трейты? нет ли противоречий канону/городу?
  выдержан ли тон/язык? нет ли копипасты лора?
- Небольшой набор «золотых» персонажей с эталонными квентами для ручной сверки
  при смене модели/промпта.

## Будущее (после MVP, заложено)

- **Обратная задача** «история → статы»: парсинг текста в предложение статов
  (вероятно, structured output + валидатор правил создания). Сложно — отдельная веха.
- **Дообучение** своей модели (LoRA/QLoRA) на датасете квент — заменяет
  `AnthropicProvider` на свой эндпоинт за той же абстракцией.
- Стриминг вывода в SPA.
